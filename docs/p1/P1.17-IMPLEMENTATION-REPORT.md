## 4. API Changes

### Heritage Listing API

**Endpoint:** `GET /api/heritage`

**Changes:**
- Now LEFT JOINs `historical_periods` and returns `period` object: `{ id, name, start_year, end_year }`
- Added `period` query parameter for filtering: `?period=<uuid>`
- Category and period filters compose correctly with AND
- Backward-compatible: entities without periods return `period: null`

### Search API

**Endpoint:** `GET /api/search`

**Changes:**
- Added `period` query parameter: `?period=<uuid>`
- Period filter applies to heritage entities only (locations pass through)
- Composes correctly with category, state, type, sort, order
- Uses existing CTE architecture

**Example:**
```
GET /api/search?q=temple&category=monument&state=Gujarat&period=<uuid>
```
