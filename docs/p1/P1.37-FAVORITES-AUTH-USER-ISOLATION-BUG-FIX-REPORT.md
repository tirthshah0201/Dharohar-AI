# Astrova — P1.37 Favorites Authentication & User Isolation Bug Fix Report

## 1. Executive Summary

Fixed a serious Favorites module bug where anonymous users could create favorites and user data was not properly isolated between authenticated users. The fix ensures favorites are exclusively per-user, authenticated-only, and properly isolated.

**Final Status: PASS**

## 2. Root Cause Analysis

### BUG-001 — Anonymous Users Could Create Favorites
- **Root cause**: `FavoriteButton` called `toggleFavorite()` without checking authentication state
- **Effect**: Anonymous users could "add" favorites to localStorage (which leaked between users)
- **Impact**: Misleading UI — appeared to work but didn't persist to database

### BUG-002 — Favorites Not Properly Isolated Between Users
- **Root cause**: `useFavorites` hook fell back to independent auth check that could desync from `useAuth`
- **Effect**: `FavoriteButton` used `useFavorites()` without shared auth state
- **Impact**: Auth state could be stale, causing incorrect favorite status display

### BUG-003 — localStorage Leaked Between Users
- **Root cause**: localStorage key `astrova_favorites` was shared across all users on the same browser
- **Effect**: User A's localStorage favorites would appear for User B after login
- **Impact**: Cross-user data leakage in anonymous state

## 3. Fixes Implemented

### Frontend Changes

| File | Change |
|------|--------|
| `frontend/components/ui/FavoriteButton.tsx` | Complete rewrite — requires auth, shows login modal when anonymous |
| `frontend/hooks/useFavorites.ts` | Complete rewrite — auth-only, no localStorage fallback, shared auth state |
| `frontend/app/heritage/[id]/page.tsx` | Pass `isFavorited`/`onToggle` props to FavoriteButton with shared auth |
| `frontend/app/heritage/page.tsx` | Pass `isFavorited`/`onToggle` props to FavoriteButton with shared auth |

### Backend (Already Correct)

The backend favorites routes were already properly secured:
- `requireAuth` on all routes
- User ID derived from JWT/session (`req.user!.id`)
- All queries filter by `user_id = authenticatedUser.id`
- DELETE uses both `user_id` and `heritage_entity_id`

No backend changes were required.

## 4. New FavoriteButton Behavior

### Anonymous User
1. Clicks heart icon
2. **Login Required modal** appears:
   - "Login Required"
   - "Please sign in to your Astrova account to save heritage places to your favorites."
   - [Sign In] [Create Account] [Cancel]
3. **No favorite record is created**
4. User can navigate to /auth to log in

### Authenticated User
1. Clicks heart icon
2. Favorite toggles via backend API
3. Backend creates/deletes `user_favorites` record with authenticated `user_id`
4. Frontend reflects the change optimistically
5. Backend failure reverts the change
