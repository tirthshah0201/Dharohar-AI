## Bug Fixes (Discovered During P1.29)

### 1. Heritage State-Counts Route Ordering (Critical)

**Issue:** `GET /api/heritage/state-counts` was defined AFTER `/:id` in the Express router. Express matched "state-counts" as an `:id` parameter, returning 404. This broke the explore page and heritage listing page state filters (both introduced in P1.27).

**Fix:** Moved `/state-counts` route definition BEFORE `/:id` in `backend/src/routes/heritage.ts`.

**Impact:** Both explore page and heritage listing page now correctly display state counts.

### 2. Chatbot Collection Intent Priority

**Issue:** Collection intent detection (`explore_collection`) was at the bottom of the `detectIntent()` priority chain. Queries like "What should I explore first?" matched `state_exploration` before reaching collection detection.

**Fix:** Added high-intent collection patterns ("first time", "beginner", "starter", "must see", "what should I") to the TOP of `detectIntent()`, before `craft_information` and `state_exploration`.

**Impact:** "What should I explore first?" now correctly returns the curated collections list. "Show me a collection of crafts" correctly returns Indian Crafts collection.

## Architecture Changes

### Authentication
- Admin API uses `X-Admin-Token` header + `ADMIN_TOKEN` env var
- Not configured by default (returns 503 with clear message)
- Designed for future JWT/session upgrade

### Favorites
- localStorage-based (no backend authentication required)
- Client-side persistence across sessions
- Heart/bookmark controls on heritage cards and detail pages

### Analytics
- Backend analytics_events table for tracking heritage views, searches, chatbot queries, collection views, favorites
- Admin-only aggregation endpoints (require ADMIN_TOKEN)
- No PII collected

## Remaining Issues

1. **Admin Auth Not Configured:** `ADMIN_TOKEN` env var not set. Admin endpoints return 503. This is intentional — admin auth requires explicit configuration before use.
2. **Favorites Not Backend-Persisted:** Favorites use localStorage. Cannot sync across devices. Backend persistence requires user authentication (future phase).
3. **Analytics Tables Empty:** No analytics data yet. Will populate as users interact with the application.

---

## Technical Debt

1. **No JWT/Session Auth:** Current auth is API-key (public) + token (admin). JWT auth needed for real user accounts and persistent favorites.
2. **Client-Side Favorites:** localStorage-based. Not server-persisted. Not cross-device.
3. **Analytics Retention:** No data retention policy. Consider adding TTL/cleanup for analytics_events.

---

## Risks

1. Admin endpoints are protected but not production-hardened. Should add rate limiting before production use.
2. localStorage favorites can be lost if user clears browser data.
