## Implementation Details

### 1. Server-Side Heritage Filtering API

**File:** `backend/src/routes/heritage.ts`

Added server-side query parameters:
- `q` — text search (name, description, category)
- `state` — filter by state name
- `sort` — sort by name, name-desc, state, category
- `order` — asc/desc

Previously only `category` and `period` were supported.

All filters compose with AND logic using parameterized queries (SQL injection safe).

### 2. Heritage Listing Uses API Filtering

**File:** `frontend/app/heritage/page.tsx`

Changed from client-side filtering to API-based filtering:
- Search, category, state, period, and sort are now sent as query params to `/api/heritage`
- Server returns pre-filtered/sorted results
- Category chips, state filter, period filter, and sort dropdown all update the API call
- URL state management added (category, state, period params)
- "Clear all" resets both state and URL

### 3. State Data Cleanup

**File:** `database/migrations/020_p1_data_cleanup.sql`

Fixed locations that used abbreviated state codes:
- MH → Maharashtra (2 locations: Ajanta Caves, Ellora Caves)
- TN → Tamil Nadu (1 location: Madurai)
- All other state codes verified and normalized

After cleanup, 12 states have consistent full-name formatting.

### 4. Heritage State Counts Endpoint

**File:** `backend/src/routes/heritage.ts`

Added `GET /api/heritage/state-counts` endpoint:
- Returns heritage entity counts grouped by state
- Uses `COUNT(DISTINCT he.id)` for accuracy
- Sorted by count descending

### 5. Explore Page Real Heritage Counts

**File:** `frontend/app/explore/page.tsx`

- State cards now fetch real heritage counts from `/api/heritage/state-counts`
- Fallback to hardcoded values if API fails
- Counts are dynamic and reflect actual database state

### 6. Search Period Intelligence

**File:** `backend/src/routes/search.ts`

- Added `period_name` to search CTE results
- JOINs `historical_periods` for heritage entities
- Search results now include period name directly

**File:** `frontend/app/explore/page.tsx`

- Search result cards display period badge using `period_name` from API
- No more client-side period lookup needed
