## 7. Runtime Bugs

### BUG-001: Heritage Detail NULL Source Crash

| Field | Detail |
|---|---|
| **Severity** | CRITICAL |
| **Module** | Heritage Detail |
| **Error** | `Cannot read properties of null (reading 'toLowerCase')` |
| **Location** | `frontend/app/heritage/[id]/page.tsx:451` |
| **Reproduction** | View any heritage entity without a source (e.g., Bandhani) |
| **Root Cause** | Backend `json_build_object` with `LEFT JOIN sources` creates `{id: null, title: null, verification_status: null}` instead of `null` when `source_id` is NULL. Frontend guard `heritage.source &&` passes because the object exists, but `verification_status.toLowerCase()` crashes. |
| **Fix** | Changed guard from `heritage.source` to `heritage.source && heritage.source.id`, and wrapped `verification_status` badge in null check |
| **Verification** | Adalaj Stepwell (HAS source) → displays correctly; Bandhani (NO source) → page loads, no crash |
| **Regression** | PASS |

### BUG-002: Auth Render-Phase Navigation

| Field | Detail |
|---|---|
| **Severity** | HIGH |
| **Module** | Authentication |
| **Error** | `Cannot update a component (LinkComponent) while rendering a different component (AuthPage)` |
| **Location** | `frontend/app/auth/page.tsx:30` |
| **Reproduction** | Visit `/auth` while already authenticated |
| **Root Cause** | `router.push("/favorites")` executed directly during render phase, not in an effect |
| **Fix** | Moved redirect to `useEffect(() => { if (!loading && user) router.push("/favorites") }, [loading, user, router])` |
| **Verification** | Authenticated user visits /auth → redirects without console error; Unauthenticated user → auth UI renders |
| **Regression** | PASS |
