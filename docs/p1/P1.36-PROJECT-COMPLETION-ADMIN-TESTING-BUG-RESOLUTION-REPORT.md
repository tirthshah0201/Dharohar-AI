## 7. Admin Module

### What Was Built

1. **Admin Login Gate** — token-based authentication with error feedback
2. **Dashboard Overview** — 9 live statistics cards with icons
3. **Heritage Management** — searchable/filterable table with category and state filters, detail inspection panel
4. **Collection Management** — collection cards with entity counts, active/inactive status, navigation links
5. **Quick Navigation** — links to heritage listing, collections, explore
6. **Refresh & Logout** — functional buttons

### Admin Security

- Missing token → ADMIN_NOT_CONFIGURED (503)
- Wrong token → ADMIN_NOT_CONFIGURED (503)
- Admin mutations protected by requireAdmin middleware
- No ADMIN_TOKEN exposed in frontend code
- Token entered by user, sent via X-Admin-Token header

### Admin API Routes (Backend)

- GET /api/admin/overview — dashboard statistics
- GET /api/admin/heritage — list with search/filter
- PUT /api/admin/heritage/:id — update heritage entity
- GET /api/admin/collections — list collections
- POST /api/admin/collections — create collection
- PUT /api/admin/collections/:id — update collection
- POST /api/admin/collections/:id/items — add item to collection
- DELETE /api/admin/collections/:id/items/:itemId — remove item
- GET /api/admin/analytics/overview — analytics data
- POST /api/admin/analytics/track — record event

### Admin Proxy Fix

The API proxy (`frontend/app/api/proxy/[...path]/route.ts`) was updated to forward `X-Admin-Token` headers, enabling the admin frontend to communicate with admin backend routes through the proxy (keeping all API keys server-side).
