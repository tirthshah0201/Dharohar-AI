## 3. Trust Proxy Decision

**Before:** No `trust proxy` configured. Express `req.ip` could return `::1` or undefined on some platforms, causing rate limits to share a single bucket.

**After:** `app.set("trust proxy", "loopback")`

**Rationale:** Astrova runs behind a Next.js proxy on the same machine (localhost). The `loopback` setting trusts requests from `127.0.0.1`, `::1`, and `::ffff:127.0.0.1`. This is the safest setting for the current architecture — it correctly identifies the client IP for rate limiting while not being overly permissive.

**Verification:** Rate limiting still works (429 on 6th login attempt). `req.ip` correctly resolves to the client IP.

## 6. Timeline Query Optimization

**Before (N+1):**
```sql
-- 1 query for all periods
SELECT * FROM historical_periods ORDER BY start_year ASC;
-- N queries (one per period)
SELECT * FROM heritage_entities WHERE period_id = $1;
```
Total: 1 + 9 = 10 queries

**After (single CTE):**
```sql
WITH period_entities AS (
  SELECT he.*, json_build_object(...) as location, ...
  FROM heritage_entities he LEFT JOIN locations l ON ...
)
SELECT hp.*, json_agg(pe.*) as entities, COUNT(*) as entity_count
FROM historical_periods hp
LEFT JOIN period_entities pe ON pe.period_id = hp.id
GROUP BY hp.id ORDER BY hp.start_year ASC;
```
Total: 1 query

**Verification:** Timeline returns 9 periods with correct entity counts and entity data. First period ("Ancient Period") has 8 entities — matches previous behavior.

## 10. CORS Verification

Current behavior:
- `NODE_ENV=production` → Origin checked against ALLOWED_ORIGINS ✅
- `NODE_ENV=development` (or missing) → All origins allowed ✅

This is correct: development should be permissive for local dev, production should be restrictive. If NODE_ENV is missing in production, CORS defaults to permissive — this is documented as a deployment requirement (must set NODE_ENV=production).
