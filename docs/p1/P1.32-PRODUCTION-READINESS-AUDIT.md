## 1. Executive Summary

Astrova is a functional heritage discovery platform with a clean three-tier architecture (Next.js → Express → Neon PostgreSQL). The core application works correctly: heritage browsing, search, collections, timeline, chatbot, favorites, and admin features all function as designed.

However, the project has accumulated significant documentation drift — the README.md is severely outdated and describes a different project scope. There are also several medium-severity production concerns: a missing `trust proxy` configuration that affects rate limiting, an N+1 query in the timeline endpoint, and missing input validation on some routes.

The application is **not yet ready for public production deployment** but is **suitable for demo/staging deployment** with the recommended fixes applied.

---

## 2. Architecture Overview

```
Browser → Next.js Frontend (:3000) → API Proxy (/api/proxy/*) → Express Backend (:3001) → Neon PostgreSQL
                                                              ↕
                                                    OpenStreetMap Nominatim (geocoding)
                                                    AI Service (:8000, optional ML intent)
```

**Verified architecture matches implementation** ✅

The proxy route correctly:
- Attaches `X-API-Key` server-side (never exposed to browser) ✅
- Forwards cookies for authentication ✅
- Forwards `Set-Cookie` headers from backend ✅
- Uses `process.env.DEMO_API_KEY` (not `NEXT_PUBLIC_`) ✅

## 3. Issues by Severity

### CRITICAL (0)

No critical issues found.

### HIGH (3)

| # | Issue | Location | Impact |
|---|-------|----------|--------|
| H1 | **README.md severely outdated** | `README.md` | Describes "Dharohar AI" (old name), Gujarat-only scope, old architecture. Misleads new contributors. |
| H2 | **Missing `trust proxy` for rate limiting** | `backend/src/index.ts` | Express `req.ip` may return `::1` or `undefined` on some platforms, causing rate limits to share a single bucket for all users. |
| H3 | **`ADMIN_TOKEN` not in `.env`** | `.env` | Admin dashboard returns 503. Not a bug per se, but undocumented operational requirement. |

### MEDIUM (5)

| # | Issue | Location | Impact |
|---|-------|----------|--------|
| M1 | **Timeline N+1 query** | `backend/src/routes/timeline.ts` | Fetches all periods, then queries entities per period in a loop. With 9 periods = 10 queries. |
| M2 | **Stale config references** | `backend/src/config/index.ts` | References `NEO4J_URI`, `NEO4J_USERNAME`, `NEO4J_PASSWORD` — unused legacy config. |
| M3 | **Missing UUID validation on media/sources** | `backend/src/routes/media.ts`, `sources.ts` | `/:id` routes accept any string without UUID validation. |
| M4 | **No pagination on list endpoints** | `heritage`, `search`, `locations`, `media`, `sources` | Returns all records. Works for 74 entities, won't scale. |
| M5 | **Frontend `.env.local` contains `DEMO_API_KEY`** | `frontend/.env.local` | Server-side only, but sharing this file exposes the key. |

### LOW (5)

| # | Issue | Location | Impact |
|---|-------|----------|--------|
| L1 | **Root `package.json` has unused dependencies** | `package.json` | `pg` and `ts-node` at root level are unused. |
| L2 | **`ApiClient.baseUrl` unused** | `frontend/services/api.ts` | Constructor accepts `baseUrl` but all requests go through proxy. |
| L3 | **No input sanitization on name fields** | `backend/src/routes/auth.ts` | Names are trimmed but not sanitized for XSS in potential future rendering. |
| L4 | **Health endpoint returns stale name** | `backend/src/routes/health.ts` | Returns `"Dharohar AI API"` instead of `"Astrova API"`. |
| L5 | **No production `NODE_ENV` guard on CORS** | `backend/src/index.ts` | Development CORS allows all origins. If `NODE_ENV` isn't set in production, all origins are allowed. |

### INFO (4)

| # | Issue | Notes |
|---|-------|-------|
| I1 | No `concurrently` in root `package.json` | `dev` script references it but it's not a dependency. |
| I2 | `frontend/.env.local` has `DEMO_API_KEY` | Correct for Next.js server-side proxy, but confusing. |
| I3 | Chatbot AI service calls have 2s timeout | Reasonable for development; may need adjustment for production. |
| I4 | No structured logging | Uses `console.error`/`console.log`. Production would benefit from structured logging. |

## 17. Known Limitations

1. **In-memory rate limiting** — Single-server only, resets on restart
2. **No refresh tokens** — JWT is stateless; cannot server-side invalidate
3. **No pagination** — List endpoints return all records (works for 74 entities)
4. **No structured logging** — Uses console.log/error
5. **No PRD.md or report.md** — Documentation gap
6. **README describes different project** — Needs complete rewrite
7. **No CI/CD** — No automated testing or deployment pipeline
8. **Test users exist** — Should be cleaned before production

## 18. Recommended Fixes (Priority Order)

### Must Fix Before Production

1. **Add `trust proxy`** to `backend/src/index.ts`:
   ```js
   app.set("trust proxy", 1);
   ```
   Without this, rate limiting may not work correctly behind a reverse proxy.

2. **Set `ADMIN_TOKEN`** in `.env` for admin dashboard access.

3. **Rewrite README.md** — The current README describes a different project ("Dharohar AI", Gujarat-only). It should describe Astrova, India-wide heritage platform.

### Should Fix

4. **Fix timeline N+1 query** — Use a single query with JOIN instead of per-period queries.

5. **Add UUID validation** to `media/:id` and `sources/:id` routes.

6. **Remove stale Neo4j config** from `backend/src/config/index.ts`.

7. **Fix health endpoint name** — Return `"Astrova API"` instead of `"Dharohar AI API"`.

### Nice to Have

8. Add pagination to list endpoints.
9. Add structured logging.
10. Remove unused root dependencies.
11. Clean up `ApiClient.baseUrl` (cosmetic).
