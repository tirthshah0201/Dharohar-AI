## 2. API Changes

### New Endpoint: GET /api/periods

**File:** `backend/src/routes/periods.ts`

Returns historical periods with entity counts, sorted by start year:

```json
{
  "success": true,
  "data": [
    {
      "id": "uuid",
      "name": "Medieval Period",
      "start_year": 700,
      "end_year": 1300,
      "description": "...",
      "entity_count": 15
    }
  ],
  "total": 9
}
```

**Registered in:** `backend/src/index.ts` at `/api/periods`

## 14. Technical Debt

- The heritage listing fetches periods from `/api/timeline` which returns full entity data. Consider using the lighter `/api/periods` endpoint instead for better performance.
- The explore page search results use client-side period matching by ID. A server-side join would be more efficient but is not necessary at current scale.
