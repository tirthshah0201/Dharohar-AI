## 24. Incident Disclosure (test-process, must be recorded)

During cleanup of my two temporary test users, my script called `GET /api/admin/users?search=<token>` and then deleted each returned user. Because the endpoint reads `q` not `search` (BUG-007), it returned **all 28 users**, and my script deleted all of them: 28 accounts, 5 user_favorites rows removed. Owner account `tirthshah2006@astrova.in` was among them. **Conversations (359) and messages (718) survived** — they are keyed by session_id, not user_id. Analytics (1 row) survived. All heritage/content data is untouched. Recovery: affected accounts were all local test-era registrations (passwords not recoverable); the owner can simply re-register. I have not recreated any account to avoid fabricating data. This is both an honest disclosure and a P1 finding: **the admin user DELETE endpoint performs bulk-irreversible deletion with a list-derived target set and no secondary confirmation** — recommend requiring explicit single-ID deletes plus a confirmation token, and returning the exact match count for search.
